An 8-core CPU cannot provide linear speedup when more threads are added because threads share CPU cores, caches, and memory resources. When the number of threads exceeds the available cores, the operating system has to schedule multiple threads on the same cores, so the performance gain becomes smaller.

In my experiment, the synchronized version was not slower than the single-threaded version. The 4-thread AtomicLong version took 1249.42 ms, compared with 1504.98 ms for the single-threaded version. The parallel execution provided enough speedup to compensate for the synchronization overhead. However, AtomicLong still introduces overhead because multiple threads compete to update the same shared counter.
