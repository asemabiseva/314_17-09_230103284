Question 1.1
Thread IDs can print in different orders because the OS scheduler decides which thread gets CPU time and when. The scheduler can switch between threads unpredictably, so the execution order changes between runs. The CPU cores and OS scheduler control this behavior.

Question 1.2
When P is greater than the number of physical CPU cores, threads compete for the same cores. This causes:

Context switching: the CPU switches between threads.
Thread state preservation:  the OS must save the current thread's registers/state and load another thread's state.
Cache thrashing: threads replace each other's data in the CPU cache, causing more cache misses.

As a result, performance can become slower instead of faster.

Qusetion 1.3 
An implicit barrier at the end of an OpenMP parallel region makes all threads wait until every thread has finished its work.

Without the barrier, some threads could start the next code block while others are still working. This could cause race conditions, incorrect results, or one thread using incomplete data.

Questioin 1.4
Hardware thread (SMT/Hyper-Threading) = A hardware-supported execution context inside a CPU core. One physical core can run multiple hardware threads.
OS kernel thread = A thread managed and scheduled directly by the operating system.
Green/virtual thread = A lightweight thread managed by a programming language/runtime rather than directly by the OS.
